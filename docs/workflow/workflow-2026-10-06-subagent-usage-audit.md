- 작성일: 2026-10-06 (KST)
- 요청: 현재 프로젝트 작업에 서브에이전트를 사용하고 있는지 확인
- 성격: **점검만 수행.** 코드·설정·에이전트 정의는 변경하지 않았고 빌드·실기기 시험도 하지 않았다.

## 1. 정의된 에이전트

| 이름 | 위치 | 역할 | 마지막 수정 |
|---|---|---|---|
| `compose-reviewer` | 프로젝트 `.claude/agents/` + 사용자 전역 `~/.claude/agents/` | Kotlin/Compose 변경분 읽기 전용 리뷰 | 2026-07-04 |
| `apk-tester` | 위와 동일 | 빌드·설치·실행·크래시 확인 | 2026-07-04 |

- 두 위치의 사본은 내용이 같다.
- `.claude/`는 **git 미추적**이다. 이 기기에서만 존재하며 저장소로 공유되지 않는다.
- 전역 사본은 처음 정의할 때 세션 루트가 다른 폴더여서 우회책으로 복사한 것이다.

## 2. 실제 사용 기록

Claude Code 세션 기록에서 Agent 호출의 `subagent_type` 값을 집계했다.
도구 설명문에 같은 단어가 들어 있어 생기는 오탐은 제외했다.

| 에이전트 | MyMap 작업에서 호출 | 결과 |
|---|---|---|
| `compose-reviewer` | 2회 | **모두 실패** — 정의를 만든 그 세션에서 호출해 "agent type not found" (에이전트는 세션 시작 시 로드됨) |
| `general-purpose` | 1회 | 성공 — `compose-reviewer`와 같은 지침을 넣어 대신 실행, 지적 2건 |
| `apk-tester` | **0회** | 한 번도 사용되지 않음 |

다른 세션 폴더에서 호출된 에이전트 2종(9회, 2회)은 **다른 로컬 프로젝트의 정의**였고,
해당 세션에서 MyMap 경로는 1회씩만 언급돼 MyMap 작업으로 보지 않았다.

**결론: MyMap의 구현·검증은 사실상 서브에이전트 없이 메인 세션이 직접 수행해 왔다.**
정의된 전용 에이전트가 실제로 성공 실행된 적은 없다.

## 3. 현재 CLAUDE.md와 어긋나는 점

### `apk-tester` (기기를 다루므로 우선 수정 필요)

1. **실행 패키지 오류** — `monkey -p com.yhgps.mymap`로 실행한다. 디버그 빌드는 이후
   `.debug` suffix가 붙어 `com.yhgps.mymap.debug`다. 그대로 쓰면 릴리스 앱을 띄우거나 실행에 실패한다.
2. **데이터 보존 절차 없음** — 지도·기록 파일 수·해시 전후 대조가 없다.
3. **금지 사항 없음** — Bash 권한이 있는데 `connectedAndroidTest`·앱 삭제·`pm clear` 금지가 적혀 있지 않다.
   기기 시험은 `am instrument`로 실행한다는 규칙도 없다.
4. 설치를 `./gradlew :app:installDebug`로 한다. 데이터는 유지되지만 CLAUDE.md는
   같은 서명 debug APK의 `adb install -r`와 서명 충돌 시 중단을 요구한다.
5. 크래시 확인 전 logcat을 비우지 않아 이전 크래시를 이번 결과로 오인할 수 있다.
6. 스크린샷 경로가 CLAUDE.md 예시(`mymap-validation.png`)와 다르다(경미).

### `compose-reviewer` (읽기 전용이라 위험은 낮음)

- 디자인 규칙은 반영돼 있으나 이후 생긴 제약을 모른다:
  `MapSelector` 사용, `MapAttribution`/`MapCredits` 출처 규칙과 `CACHE_VERSION`,
  내보내기 원본 보존(영상용 단순화 금지), `java.time` 사용 제한, `MAX_LIVE_POINTS` 통계 금지.
- 정의 파일에 CLAUDE.md를 먼저 읽으라는 지시도 없다.

### 공통

- 전역 사본이 남아 있어 **다른 프로젝트 세션에도 MyMap 전용 에이전트가 노출**된다.
  지금은 세션이 MyMap 루트에서 열리므로 프로젝트 사본만으로 충분하다.

## 7. 후속 — 정의 검토 의견 반영과 정정 (같은 날)

별도 검토([workflow-2026-10-06-subagent-definition-review.md](workflow-2026-10-06-subagent-definition-review.md))가
정의 보완 4건과 크래시 지적 정정을 제시했다. **각 항목을 직접 확인한 뒤** 반영했다.

### 정정 1 — 출처 링크 크래시 지적은 틀렸다

앱이 실제로 쓰는 버전(Compose UI·foundation **1.9.2**, Gradle 의존성으로 확인)의 소스를 직접 읽었다.

- `AndroidUriHandler.openUri`: 브라우저를 찾지 못한 `ActivityNotFoundException`을 `IllegalArgumentException`으로 바꿔 던진다.
- `TextLinkScope.handleLink`: 리스너가 없는 `LinkAnnotation.Url`의 기본 처리에서 그 `IllegalArgumentException`을 잡아 무시한다
  (소스 주석: 크래시를 피하려고 조용히 실패하게 했다).
- `MapAttribution`은 리스너 없이 이 기본 경로를 쓴다.

→ 이 버전에서 "브라우저가 없으면 크래시"는 맞지 않다. 6장에서 "소스를 찾지 못했다"고 한 것은
비소스 jar만 찾도록 검색 조건을 잘못 잡은 탓이었다(`*-sources.jar`이 캐시에 있었다).
링크를 열지 못했을 때 아무 반응이 없는 것은 별도 UX 개선 후보다. 실기기 재현은 하지 않았다.

### 정정 2 — 정의 캐시는 "강한 정황"이지 확정이 아니다

6장의 단정 표현을 바로잡았다(해당 위치에 정정 표시). 새 세션 재확인 전까지 원인은 미확정이다.

### 정의 보완

| # | 지적 | 확인 | 반영 |
|---|---|---|---|
| 1 | 해시 명령이 오류를 숨겨, 확인 실패가 "기록 없음"으로 보일 수 있음 | `2>/dev/null`과 `cd files &&` 때문에 `run-as` 실패 시 빈 출력 — 사실 | 상태 줄(`STATUS=OK`/`NO_FILES_DIR`/`HASH_FAIL`)과 종료 코드로 판정. 확인 실패면 **중단** |
| 2 | `am instrument`만으로는 안전하지 않음 | 시험 코드가 실제 `files/`를 지우면 실행 방식과 무관 — 사실 | 실행 전 시험 클래스의 초기화·정리 코드, 저장 경로(실제 vs 격리), 삭제·쓰기 호출, opt-in 조건 확인. 실제 지도·기록에 닿거나 불확실하면 **실행하지 않고 보고** |
| 3 | `logcat -c`가 진단 로그를 지우고, 검색에 다른 앱 오류가 섞임 | 사실 | `logcat -c` 금지 목록에 추가. 실행 직전 기기 시각 이후 **크래시 전용 버퍼**에서 `Process: com.yhgps.mymap.debug`만 확인. 3~5초 관찰은 "실행 직후 크래시 없음"으로만 보고 |
| 4 | 리뷰 범위가 지나치게 엄격해 호출 관계 검증을 막음 | "지정된 파일만 본다" — 사실 | 지적 대상은 지정 범위로 제한하되, 근거 확인을 위한 호출부·정의부·라이브러리 소스 열람은 허용. 추정은 "확인 필요"로 표시 |
